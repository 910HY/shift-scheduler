# 今日編更｜即日人手調度（手機 MVP）

現場用、大掣、少打字嘅即日編更原型。即時改班（走咗／頂替／對調）只改本地狀態；每一次「重算」或「生成草稿」都呼叫後端 **OR-Tools CP-SAT**（`ShiftSchedulerWithConstraints`）。已過時段同「已確認」格會鎖住，求解器唔會覆寫。

舊版桌面設定頁仍可喺 `/desktop` 用。

## 本機跑

```bash
python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

瀏覽器開 <http://127.0.0.1:8080>。

### 用 iPhone Safari 試

1. 電腦同 iPhone 連同一個 Wi‑Fi。
2. 查電腦區網 IP（macOS / Linux：`ipconfig getifaddr en0` 或 `hostname -I`）。
3. iPhone Safari 開 `http://<電腦IP>:8080`。
4. （可選）分享 → 加入主畫面，當 PWA 用。
5. 如果電話開唔到：檢查防火牆有冇擋 8080，或用 USB 連接 + 本機端口轉發。

部署到 Render 等平台時，沿用 `Procfile` 嘅 gunicorn（timeout 120 秒）。

### iPhone 硬重新載入（舊 CSS 會令時間軸滑唔到）

電話若仍見到舊版（時間軸截到半日、冇「左右滑睇其他時間」、左右滑無反應），Safari 唔好只拉下更新：

1. 開網站 → 撳 **aA**（或分享）→ **重新載入**；仍然唔得就 **設定 → Safari → 進階 → 網站資料** 清呢個站。
2. 如果已「加入主畫面」，刪咗舊圖示再開一次（PWA 會鎖住舊 service worker）。
3. 呢版靜態檔 query 係 `app.css?v=9` / `app.js?v=9`，service worker cache 名 `shift-mobile-v9`。`app.js` / `app.css` 唔再 precache，但仍要硬重新載入先換到新 DOM（左欄固定、右欄獨立 `overflow-x: auto`）。

## iPhone 上建議試嘅步驟

示範數據用編號人手 **1–8**（唔再用阿明／小華呢啲示範名）。預設「而家」係 **09:45**（排班 09:00–13:00 之內），所以 09:00–09:30 已過並鎖住；編號 **1** 喺 09:00–10:00 **ARR-1** 已確認。唔使先重算都可以改。

**改示範時間：** 撳今日藍色 chip，或「更多 → 改示範而家」，用系統時間選擇器（iPhone 唔再用會食變更嘅下拉選單）。「將而家設為開始時間」一鍵調去排班開始。改排班開始時，如果舊嘅「而家」會鎖死成段可見格，會自動設成開始時間並 toast。**生成草稿**會忽略示範「而家」嘅過去鎖定，用 OR-Tools 填晒需求格。

1. **今日**：左右滑時間軸睇晒排班（窄屏會出「左右滑睇其他時間」同右邊淡出提示，第一次橫滑之後會收）。崗位名固定喺左邊，只有時間軌道會橫向捲動。按 ARR／DEP／KIOSK (A)／KIOSK (D) 分組；**分類標題列（DEP / KIOSK (A)）本身冇色塊係正常**，編號軌道 1、2 先有班。如果某類需求遲過排班開始（例如 KIOSK 由 09:30），早晨嗰截會空，向右滑就見到編更。
2. 撳一格有人嘅未來班 → **標記之後空缺**：呢位同事之後未鎖定班會變空缺（即時，唔等求解器）。
3. 撳空缺 → **派人頂呢格**，或撳有人嘅班 → **搵人頂替**。
4. **對調給其他人**：揀兩項未鎖定班 → 確認對調。已確認／已過時段唔會改動。
5. **人手**：睇每位工作／休息分鐘同進度條。接近連續工時上限會出黃／橙色提示，**唔會鎖死編輯**。
6. **重算**：撳「重算未鎖定時段」。應見到計時，然後回到今日；已確認同已過時段不變，剩餘空缺會列喺重算頁。
7. **生成草稿**亦會行 OR-Tools，而且**唔帶**而家嘅過去／確認鎖定（方便由零再排；示範時間太遲都仍然填得到早更）。
8. **更多 → 崗位要求**：只有四類 **ARR / DEP / KIOSK (A) / KIOSK (D)**。用 +/- 改**崗位數**（例如 ARR=4 會變成 ARR-1…ARR-4），再加／刪需求時段。時間軸同「重算」會即時跟住更新。減崗唔會洗走剩餘軌道嘅已確認／已過時段。
9. **更多 → 人手名單**：由 **1** 至 **20**（最高 **99**，要 `1 ≤ 由 ≤ 至 ≤ 99`）撳「批量加入」。會清走舊中文示範名同佢哋嘅編更，只留編號；已有編號會跳過。可以逐個加／刪，或「清空人手」。人手頁同時間軸會用大號數字顯示。
10. **建議驗證**：排班 06:30–13:00，示範而家 06:30，人手 1–10，ARR／DEP／KIOSK (A)／KIOSK (D) 都設崗位數同需求時段。撳「生成草稿」→ 左右滑到最後一個時段（例如 12:30）。人手 ≥ 同時段崗位數時，編號軌道應幾乎填滿，剩餘「空缺」會喺 toast／重算頁列明。分類標題列仍然冇假色塊。
11. **更多** 亦可改示範時間、約束、重設示範數據（重設後仍然係編號 1–8）。

編更會存 `localStorage`（key：`shift-mobile-v4`）。若舊資料嘅示範時間會鎖死成段窗口，載入時會重置為排班開始。

## 重算點樣鎖格（同限制）

- 前端把 **已過時段** 同 **已確認** 嘅指派，以及「走咗」之後嘅不可用時段，一齊傳去 `POST /schedule`（「重算」）。
- **生成草稿**傳空鎖定；套用結果時忽略示範「而家」造成嘅已過鎖定，所以早更空缺都填得到。
- 如果示範「而家」遲過成段可見需求，今日／重算會出提示；改排班時段會自動把示範時間夾返入窗口。
- 求解器以員工名入模（唔再只得 K1…Kn），工作量平衡改為**軟目標**（唔再硬性 ±1，避免現場人手不均就無解）。
- 崗位覆蓋係**主目標**（未填格權重遠高過工作量平衡）：人手足夠覆蓋同時段需求時，應盡量填滿。填唔晒就回報 `unfilled_job_slots`，介面繼續顯示空缺同剩餘格數。
- 若完整硬規則（連續工時、連崗、強制落場）加鎖定之後 **INFEASIBLE**，或只係 **FEASIBLE 但仍有大量空缺**（棋盤式休息造成嘅「空缺」），會自動再試：
  1. `relaxed`：只喺完整規則無解時，跳過同鎖定格重疊的連續工時／連崗窗
  2. `fill`（優先填滿空缺）：放寬連續工時同同一崗位連續，CP-SAT 以未填格為第一目標
  3. 仍無解：回傳鎖定格 + 其餘留空（`FEASIBLE_LOCKS_ONLY`），並列出剩餘空缺

每一次嘗試都仍然跑 CP-SAT；最後一步只係合併結果，唔會用啟發式取代重算。

每位軌道每 30 分鐘格只派 1 人，方便沿用而家 OR-Tools 一人一崗編碼。四類崗位嘅「崗位數」會展開成 `ARR-1`、`KIOSK-A-2` 呢類代碼再交俾 `/schedule`。
